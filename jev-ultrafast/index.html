Jev Ultrafast Architecture

Educational explainer: browser agent using DOM-indexed actions instead of screenshot analysis. Claimed 7s Google Flights search for ~$0.0039.

Architecture mode:
1
Observe DOM State
Parse page structure, extract interactive elements with indices
2
Build Indexed Action List
Generate typed action space: click[0-47], type[field_3], scroll[section_2]
3
Policy Picks Action Index
Small LLM selects action from discrete space (not vision model)
4
Execute Action
Browser performs click/type/scroll directly via automation API

DOM-Index Agent (Jev)

Search time ~7s
Cost per run ~$0.0039
Primary input DOM structure
LLM usage Text only (typing)

Screenshot Agent

Search time ~40-60s
Cost per run ~$0.30-0.50
Primary input Full screenshots
LLM usage Vision model every step
Example: Google Flights ZRH→LON cost breakdown
Jev index ops: 70% Text LLM: 30%
Source: Inspired by @gregpr07's post about browser-use/jev-ultrafast (MIT license, Browser Use + TypeSafe Jev).

Educational only: This is an architecture explainer toy — not the real agent. No actual browser automation, no API keys required. The ~7s / ~$0.0039 metrics are from the original post.

Key innovation: DOM-indexed action space eliminates expensive vision model calls for every page state, falling back to small text LLM only for typing operations. Actions are discrete indices into the interactive element list.
